# 임시 공유

임시 공유는 기존 ngrok 계정의 HTTPS 주소를 사용한다. 정식 운영 배포가 아니며 컴퓨터, 인터넷, 공유 백엔드, ngrok가 실행 중일 때만 접속할 수 있다. 무료 플랜에는 방문 안내 화면과 사용량 제한이 있을 수 있다. [ngrok 안내](https://ngrok.com/docs/pricing-limits/free-plan-limits)

## 시작

1. 기존 백엔드 실행 창에서 Ctrl+C로 종료한다. 같은 H2 DB를 두 서버가 동시에 열면 안 된다.
2. 프로젝트 루트의 `run-share.cmd`를 실행한다. 화면과 백엔드를 빌드하고 전용 설정으로 시작한다.
3. 실행 창에 표시되는 HTTPS 주소로 접속하고 지인에게 전달한다. 이 주소는 ngrok 계정 상태에 따라 바뀔 수 있으므로 매번 표시된 주소를 확인한다.

빌드는 Spring Boot가 `frontend/dist`만 제공한다. Vite 개발 서버, 프로젝트 폴더, `.env`, DB 파일은 공개 대상이 아니다. 외부 API 요청도 같은 주소로 전송된다. 로컬 백엔드 포트는 127.0.0.1:18787이며, HTTPS는 ngrok에서 처리한다.

## 사용 범위

- 기존 DB와 SMTP 설정을 그대로 사용한다. 가입·찜·후기·문의·다이어리 테스트 데이터도 **실제 로컬 DB에 저장된다**. 테스트 참여자에게 알려두고 소수에게만 공유한다.
- 이메일 인증 가입과 일반 아이디/이메일 로그인을 사용한다. 별도 메일 앱 비밀번호를 화면에 입력하거나 배포 파일에 넣을 필요가 없다.
- 임시 공유 모드에서는 기본 공개 테스트 계정 `test1`, `test01`, `demo`의 로그인과 관리자 경로를 차단한다. 기존 계정이나 기록을 삭제하지 않는다.
- 구글·네이버 로그인은 공유 모드에서 비활성화한다. 로컬 개발 설정은 변경하지 않는다. 소셜 로그인이 필요하면 고정 도메인 등록 및 각 공급자 설정을 별도로 검증해야 한다.
- 세션은 공유용 쿠키 이름, HttpOnly, Secure, SameSite=Lax를 사용하며 CSRF 검증을 유지한다. 정확한 공유 HTTPS 출처만 CORS에서 허용한다.
- 기존 업로드·저장 용량·호출 횟수 제한은 공유 모드에서도 유지한다.
- ngrok 로컬 요청 본문 검사 기능은 `--inspect=false`로 끈다. HTTPS 터널 제공자는 트래픽 전달 경로에 포함된다.
- 임시 공유 전에 채팅 등에 노출한 API 비밀키와 메일 앱 비밀번호를 교체하는 것이 좋다. 링크가 있는 누구나 접근할 수 있으며 초대 전용 접근 제어가 아니다.

## 종료 및 복귀

`stop-share.cmd`는 127.0.0.1:18787로 연결한 ngrok 프로세스만 종료한다. 백엔드 창도 Ctrl+C로 종료하면 된다. 컴퓨터를 끄면 접속도 중단된다.

원래 로컬 개발로 돌아가려면 공유 백엔드를 종료하고 `run-backend.cmd`를 실행한다. 개발 프론트의 5173 포트는 기본 8080 백엔드를 사용하므로 공유 모드 동안에는 발급받은 HTTPS 주소로 테스트한다.

이 설정은 Windows 서비스 자동 시작이나 정식 서버 배포를 설치하지 않는다. 기존 `.env`, 운영 관리자 지정, 로컬 소셜 로그인 설정을 덮어쓰지 않는다.
