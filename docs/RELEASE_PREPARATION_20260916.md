# 제출 전 추가 정리: 2026-09-16

## 적용한 변경

- 전시 배지는 획득한 배지 중 최대 1개이며, 전시하지 않는 것도 가능하다. 다른 배지를 누르면 교체한다. 서버도 2개 이상 저장을 거부한다. 이전에 여러 개를 저장한 계정은 저장 순서의 첫 배지만 반환·표시하며 획득 기록은 삭제하지 않는다. 다이어리 스티커 제한은 별개다.
- 장소 검색은 `COUNT(*) OVER()`로 결과 개수와 페이지 ID를 한 번의 조건 검색에서 조회한다. 해당 페이지의 상세 행만 추가로 가져오므로 조건 검색 두 번과 전체 행 정렬 비용을 줄인다. 새 검색 인덱스·캐시·DB 엔진 변경은 없다.
- 마지막 페이지를 넘는 요청은 기존처럼 마지막 페이지로 보정한다. 검색어·지역·카테고리·종류·개인화·정렬 규칙은 유지하고 비공개 행은 상세 조회에서도 제외한다.
- `--check-deployment` CLI와 `scripts/check-deployment.ps1`을 추가했다. 필수 실행 파일, HTTPS 출처, 관리자 지정, 테스트 계정 정책, 네이버 콜백, H2 파일 존재, 웹 공개 경로 분리, 백업 설정을 검사한다. 운영 DB를 열거나 생성하지 않으며 설정값·비밀번호를 출력하지 않는다.
- 320px 프로필 편집창의 가로 넘침도 해당 창의 그리드 폭만 조정해 수정했다.

## 검증

- 백엔드 전체 160개 테스트 통과(실제 백업 사본 벤치마크 포함), 오류·실패·건너뜀 0.
- 프론트 58개 테스트 및 운영 빌드 통과.
- 배포 점검 전용 8개 테스트: 누락 DB·설정·파일, 테스트 관리자, 잘못된 소셜 콜백, 공개 DB/백업 경로, 같은 백업 사본 폴더, 외부 XML 엔티티 차단, 비밀값 출력 방지를 포함한다.
- 브라우저의 분리된 UI 테스트에서 기존 3개 선택을 1개로 제한, 선택 교체, 전시 해제를 확인했다. 390px 화면 확인 및 320px·1280px에서 가로 넘침이 없음을 확인했다. 테스트 화면은 실제 계정이나 API를 사용하지 않았다.
- 격리 DB의 기존 SQL과 새 SQL은 바다·카페·강릉 바다·산책·캠핑·바다 카페의 전체 개수, 반환 행과 순서가 동일했다. 별도 테스트로 페이지 합치기, 마지막 페이지 보정, 빈 결과, 지역 필터를 확인했다.

실제 백업의 장소 49,754건을 별도 폴더로 복원하고 새 JAR를 루프백 18789에서 실행해 HTTP로 측정했다. 이 테스트 서버는 종료했고 사용자의 기존 공유 서버는 재시작하지 않았다.

## 적용과 남은 일

2026-09-16 20:09경 사용자가 `run-share.cmd`를 다시 실행했고 공유 서버와 외부 HTTPS 상태 응답을 확인했다. 새 검색 SQL과 서버 배지 제한이 포함된 JAR로 재시작했다. 같은 DB를 여는 백엔드를 동시에 시작하지 않는다. 프론트 운영 빌드도 다시 생성했다.

학교 서버의 HTTPS, 실제 메일, 소셜 로그인 제공자 등록, 관리자 계정 존재 확인, 파일 권한, 재부팅과 최종 DB 복원은 여전히 현장 검증 대상이다. 오프라인 점검 통과는 배포 승인이나 전체 서비스 정상 보장이 아니다.
