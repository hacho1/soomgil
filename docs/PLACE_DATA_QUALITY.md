# 장소 데이터와 검색 표시 정리

## 적용 범위

2026-09-15. 기존 장소 ID, 회원, 찜, 후기, 다이어리를 삭제하지 않고 공식 콘텐츠 분류와 검색/상세 표시를 정리한다. 공식 데이터의 제공 범위와 동기화 항목은 [한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do)를 기준으로 한다.

## 분류와 검색

- `places.tour_content_type`에 수집 응답의 `contenttypeid`를 별도로 보관한다. 알려진 코드만 저장하며 누락된 코드나 이름만으로 여행 코스라고 단정하지 않는다.
- 25는 여행 코스, 32는 숙박, 38은 쇼핑, 15는 축제·행사로 구분한다. 여행 코스/숙박/행사 이름에 카페·숲길·캠핑이 들어 있어도 장소 종류를 덮어쓰지 않는다.
- `content_kind`는 `place`, `course`, `unknown`이다. 공식 분류가 없는 복구 자료는 `unknown`으로 남고, 승인된 사용자 제보는 `place`다.
- `/api/places/search`에 선택적인 `kind=place|course` 조건을 추가한다. 생략 시 기존처럼 전체이며 미분류 자료도 남는다. 알 수 없는 조건은 400, 비공개/미승인 항목은 모든 종류에서 제외한다.
- 화면의 전체/장소/여행 코스는 URL에 저장되어 뒤로가기와 페이지 이동에도 유지된다. 장소/코스 조건은 확인된 분류만 포함하므로 전체 건수와 두 조건의 합이 다를 수 있다.
- 추천순은 정확한 장소명 일치를 최우선으로 유지한다. 이후 주소와 유효한 국내 좌표가 있는 장소, 일부 위치 자료만 있는 장소, 위치 자료가 없는 자료, 공식 여행 코스 순으로 나눈 뒤 기존 주제·취향 정렬을 적용한다. 이름순은 유지한다.
- `place_quality`는 이 순서를 위한 내부 값이며 평점·인기도·정보 정확도의 보증이 아니다. 사진이 없다는 이유만으로 검색 결과를 삭제하지 않는다.
- 홈 추천은 주소와 좌표가 있는 후보를 사용하며 공식 여행 코스는 제외한다. 주변 장소 추천에서도 코스를 개별 방문 지점으로 넣지 않는다. 기존 찜/공유 링크로 코스 상세를 여는 것은 유지한다.

## 기존 DB 보완

- 추천 색인 버전 2로 기존 행을 500개씩 재계산한다. 이름으로 공식 타입을 추정하지 않으며 원본 계정/장소 연결을 보존한다.
- 정기 수집 상태에 `catalog_version`, `run_catalog_version`을 추가한다. 구버전 목록은 누락 날짜 갱신을 우선한 뒤 전체 메타데이터 수집을 한 번 진행한다.
- 진행 중인 페이지는 중간부터 이어가며, 구버전으로 시작한 전체 수집은 완료해도 새 버전 전체 수집으로 간주하지 않는다. 새 버전의 첫 페이지부터 끝까지 처리한 후에만 보완 완료를 기록한다.
- 기존 일일 한도, 실패 대기, 트랜잭션 체크포인트, 서버 간 잠금, 관리자의 일시정지 상태를 유지한다. 수집이 꺼져 있거나 API가 실패하면 완료를 주장하지 않는다.
- `/api/places/status`의 `sync.contentTypesRefreshed`는 새 분류 필드를 포함한 전체 수집 완료 여부다. 제공자가 타입을 누락한 자료까지 전부 분류됐다는 뜻은 아니다.
- 전체 보완은 서버 시작 후 백그라운드에서 진행되므로 시작 직후 일부 자료는 전체에만 보일 수 있다. 새로운 종류가 확인되면 기존 수집 저장 경로에서 바로 재색인한다.

## 화면 표시

- 검증된 0~5 범위의 숫자가 있을 때만 평점을 렌더링한다. `평점 확인 중`이나 빈 평점 영역을 반복 표시하지 않는다.
- 관광공사 사진 또는 사용자 제보 사진은 유지한다. 임의의 Unsplash/참고 사진으로 빈 사진을 대체하지 않는다. 사진 누락/로드 실패는 같은 크기의 사진 없음 영역으로 처리한다.
- 카드의 빈 주소 줄과 앞뒤가 비어 있는 구분점을 제거한다. 상세에서 주소가 없으면 한 번만 안내한다.
- 매칭 실패를 무한히 진행 중인 것처럼 표시하지 않는다. 조회 중, 자료 미제공/매칭 자료 없음, 일시 조회 지연을 구분한다. 자료 없는 장소를 한적하다고 만들지 않는다.
- 공식 여행 코스 상세는 코스 소개·소요시간·길이를 제공하는 범위에서 표시한다. 단일 지점 혼잡도와 코스 전체의 반려동물/무장애 가능 여부를 주장하지 않으며, 코스에 다시 주변 자동 코스를 붙이지 않는다.

## 검증 범위

공식 타입 우선/잘못된 타입 거절, 미분류 보존, 실제 장소 우선/정확한 코스명 일치, 종류 필터와 비공개 보호, 장소 수/기존 ID 유지, 분류 보완 재시작/일시정지, 코스 상세 API 호출 범위, 평점과 사진 표시의 경계값을 자동 테스트한다. 실제 실행 서버 적용에는 백엔드 재시작이 필요하다.

기존 API에 타입이 없던 약 5만 건의 자료가 모두 분류됐다는 주장이나 현장 혼잡도/운영 여부를 검증했다는 주장은 하지 않는다.

## 구현 시 검증 결과

- 백엔드 119개 테스트 통과(실제 DB 백업 테스트 포함, 실패/생략 0개), 프론트엔드 50개 통과. 백엔드 JAR와 프론트 배포 빌드 성공.
- 검증된 49,754개 장소의 DB 백업을 임시 디렉터리에 복원해 색인 버전 2를 적용했다. 원본 DB는 열지 않았고 장소 수는 전후 동일했다. 이번 개발 PC 측정의 일괄 보정은 약 117초였다.
- 백업의 `바다` 검색은 887건을 유지했다. 앞부분은 가사동백숲해변·가진해변·갈목해변·감추해변·강동몽돌해변·강문해변으로 바뀌었다. 공식 타입을 외부에서 새로 수집한 검증은 아니며, 위치 정보 우선 정렬까지 확인한 결과다.
- 백업 SQL 측정: 바다 첫 조회 약 2.4초, 강릉 바다 0.7초, 산책/캠핑/바다 카페 약 0.5초. 추천 후보는 약 1.1~1.7초였다. 빌드가 함께 실행된 개발 PC 결과이며 전체 HTTP/이미지 로딩 시간과 다르다.
- 320px/390px 브라우저에서 새 공통 카드의 가로 넘침, 빈 주소 줄, 근거 없는 평점 문구, 임의 참고 사진이 없는 것을 확인했다. 일반 장소 상세에서도 평점 빈 영역 없이 혼잡도와 공식 이용 안내를 유지했다.
- 이 기록 작성 시 실제 실행 서버는 재시작 전이다. 종류 필터와 분류 보완은 새 백엔드 실행 후 별도 확인이 필요하다.
