# 기존 혼잡도 계산식 복원

반영일: 2026-09-14.

## 원래 코드의 근거

현재 작업의 로컬 대화 기록에서 복구 전 Java 코드의 `getCrowdLevel(double value)`를 확인했다. 2026-06-12와 2026-06-16의 코드 조회/수정 기록에 동일한 구간이 남아 있다. 2026-09-13에 임시로 적용했던 35/75 구간은 원래 식이 아니므로 제거했다.

```java
private String getCrowdLevel(double value) {
    if (value >= 70) return "붐빔";
    if (value >= 40) return "보통";
    return "한적함";
}
```

- 유효한 집중률 0 이상 40 미만: 한적함.
- 40 이상 70 미만: 보통.
- 70 이상 100 이하: 붐빔.
- 기존 코드의 결측치 대체값 999를 붐빔으로 취급하는 오류는 복원하지 않았다. 결측, 비수치, 범위 밖 응답은 등급을 만들지 않는다.
- 평점 및 숨길 점수 계산은 변경하지 않았다.

수치는 연결된 관광공사 집중률 방문자 추이 예측 API의 당일 `cnctrRate`를 사용한다. 과거 통신 데이터를 분석한 예측 상대값이지 실시간 현장 방문자 수는 아니다. [공식 API 설명](https://www.data.go.kr/data/15128555/openapi.do)

## 검색 결과 조회 수정

이전 복구본은 상세/미리보기를 열 때만 집중률을 조회하고 검색 목록에는 캐시만 적용했다. 그래서 미조회 상태까지 자료 없음으로 보였다.

- 검색 페이지의 현재 6개 카드와 지도 하단의 현재 6개 장소에서 `/api/places/{id}/crowd-info`를 순차 조회한다. 결과가 도착한 카드부터 등급을 갱신한다.
- 목록 밖의 모든 장소를 한 번에 호출하지 않는다. 기존 서버의 캐시와 일일 한도를 유지한다.
- 검색어/페이지/지도 영역 변경 시 이전 요청을 취소하고 늦게 도착한 값을 새 화면에 적용하지 않는다.
- 혼잡도 필터에서는 먼저 후보 24곳을 확인하고 추가 후보는 '다음 24곳 혼잡도 확인'으로 이어간다. 확인된 결과 수와 미확인 수를 구분한다. 필터 때문에 아직 조회하지 않은 장소가 모두 사라져 실제로 없는 것처럼 보이지 않게 한다.
- 자료가 있는 장소는 한적함/보통/붐빔을 그대로 표시한다. 미조회는 확인 전, 요청 중은 확인 중, 네트워크/한도 문제는 조회 지연, 지역 코드 미연결은 연결 확인 중, 정상 조회 후 해당 당일 값이 없으면 미제공으로 표시한다.
- 네트워크 오류 시 다시 확인할 수 있다. 확인 실패를 한적함으로 대체하지 않는다.
- 이미 저장한 예측 등급 문자열도 원래 수치에서 재계산한다. 임시 구간으로 계산한 등급이 DB 캐시에 남아 있어도 40/70 기준을 사용한다.

## 검증

- 백엔드 59개, 프론트 32개 테스트 통과. Java 실행 JAR 및 Vite 프로덕션 빌드 성공.
- 39.99/40/69.99/70 경계값, 999/NaN 등 제외, 기존 캐시 재계산, 평점 불변, 정상 빈 응답과 오류 구분, 순차 카드 조회와 검색 취소를 검사했다.
- 실제 간현관광지 검색에서 상세를 열지 않고 한적함이 표시되는 것을 확인했다. 한적함 필터도 같은 결과를 유지했다.
- 장령산자연휴양림은 정상 API 조회 후 당일 매칭 값이 없어 미제공으로 표시됨을 확인했다.
- 320px와 390px 모바일 검색 화면에서 가로 넘침이 없음을 확인했다. 검증 시 사용자의 기존 다크 모드를 유지했다.

모든 관광공사 장소에 집중률 자료가 있는 것은 아니다. API에 등록된 장소명/지역/당일 자료가 일치하는 경우에만 등급을 산정하며, 미연결 장소의 구체적 매칭 확대는 별도 과제다.
