# 네이버 로그인 연결

연결일: 2026-09-13

## 현재 설정

- 네이버 애플리케이션: `soomgil`, 개발 중 상태.
- 기존 Windows App 환경에 PC 웹 환경을 추가했다.
- 서비스 URL: `http://127.0.0.1:5173`
- Callback URL: `http://127.0.0.1:5173/api/auth/naver/callback`
- `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `NAVER_REDIRECT_URI`는 프로젝트 루트의 비공개 `.env`에서 백엔드가 읽는다. 설정 변경 후 백엔드를 재시작한다.
- `localhost`와 `127.0.0.1`은 다른 주소다. 현재 등록 주소인 `127.0.0.1:5173`에서 시작해야 인증 세션이 이어진다.
- 개발 중인 앱은 개발자센터 멤버관리에서 허용된 계정으로 시험한다. 일반 사용자에게 공개하려면 실제 서비스 도메인을 등록하고 네이버 검수를 진행해야 한다.

## 로그인 흐름

1. 로그인 또는 회원가입 화면에서 네이버 버튼을 누른다. 별도 팝업 없이 같은 탭에서 이동한다.
2. 백엔드가 세션에 10분 유효한 무작위 state를 저장한다. 로그인 화면의 자동 로그인 선택도 보관한다.
3. 네이버 인증 후 Callback에서 state를 검증하고 소비한다. 토큰 교환과 회원 정보 조회는 백엔드에서만 처리한다.
4. 기존 네이버 회원은 네이버 고유 식별자로 로그인한다. 제공 이메일이나 닉네임이 변경되어도 같은 계정으로 처리한다.
5. 새 회원은 숨길에서 닉네임과 개인정보 수집·이용 동의를 확인한다. 네이버가 이메일을 제공하지 않은 경우 연락처 이메일을 입력받는다.
6. 가입 완료 후 여행 취향 설정으로 이동한다. 기존 찜 요청이나 돌아갈 화면도 이어진다.

## API와 데이터

- `POST /api/auth/naver/start`: CSRF 검증 후 네이버 인증 URL 반환.
- `GET /api/auth/naver/callback`: 세션과 state 확인, 인증 결과 처리, 고정된 숨길 완료 화면으로 이동.
- `GET /api/auth/naver/pending`: 같은 세션에 저장된 가입 확인용 정보 조회.
- `POST /api/auth/naver/complete`: 동의와 닉네임 검증, 회원 생성, 기존 숨길 세션 로그인.
- `DELETE /api/auth/naver/pending`: 진행 중인 인증과 가입 확인 정보 취소.
- `user_accounts.auth_provider='naver'`, `provider_id`에 네이버 고유 식별자를 저장한다. `(auth_provider, provider_id)` 유일 인덱스로 중복 회원을 방지한다.
- 네이버 회원에게 숨길용 비밀번호나 가짜 휴대전화번호를 만들지 않는다. 네이버 프로필 이메일을 받았다는 이유만으로 `email_verified=true`로 바꾸지 않는다.
- 이미 다른 방식으로 가입한 이메일은 자동 병합하지 않고 기존 로그인 방법을 안내한다.
- 네이버 access token과 Client Secret은 프론트 응답, 리다이렉트 URL, 앱 로그에 포함하지 않는다. 토큰은 회원 정보 조회에만 쓰고 보관하지 않는다.
- 인증 취소, 만료, 공급자 오류는 재시도 가능한 숨길 화면으로 돌아온다. 공급자의 원문 오류는 사용자 화면에 노출하지 않는다.

## 확인 범위

- 테스트 DB에서 신규 가입, 동의 및 닉네임 검증, 중복 이메일, 기존 회원 재로그인, 자동 로그인 쿠키, CSRF, 다른 세션의 state, state 재사용, 인증 취소/실패를 확인했다.
- 모바일 로그인 화면의 버튼 배치와 실제 네이버 `soomgil 로그인 중` 화면 이동을 확인했다.
- 실제 네이버 계정의 비밀번호 입력과 최종 동의 이후의 실연동 검증은 계정 주인이 진행해야 한다. 테스트 DB의 공급자 응답은 모의 응답을 사용한다.
- 이메일 인증 서비스는 이번 네이버 연동 범위에 포함하지 않았다.
